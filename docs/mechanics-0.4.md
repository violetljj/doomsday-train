# 0.4 由职责决定联动

用户确认取消风火的方向特例，采用进攻、增益、减益分类。位置决定邻接关系，车厢职责决定联动执行者；调换同一对车的前后不改变配方。

## 五种车厢与五个功能槽

机车不占功能槽。发车时第一槽为火炮车，后面四槽为空；五槽按车头到车尾排列，模型中心坐标为 `SLOT_Y=[40,-70,-180,-290,-400]`。只有直接相邻的槽位可以联动，因此最多同时存在四条联动边，空槽不传递辅助。

| 类型 | 车厢 | 独立作用 | 联动职责 |
| --- | --- | --- | --- |
| 进攻 | 火炮、喷火、电弧 | 发射炮弹、喷火、电击 | 执行联动攻击 |
| 增益 | 风扇 | 推开普通敌人 | 用气流辅助相邻进攻车 |
| 减益 | 冰霜 | 低伤害并减速普通敌人 | 为相邻进攻车提供冰霜效果 |

只有进攻＋增益、进攻＋减益产生联动。进攻＋进攻、增益＋减益、同类相邻都独立工作，空位切断联动。增益与减益保留各自独立功能，不会因为没有邻接武器而失去所有作用。

增益、减益车自身应零伤或低伤。当前风扇零伤害；冰霜基础每1.6秒造成4点伤害，以减速为主。辅助后的强联动攻击归进攻车执行。增益＋减益的特殊联动留作后续设计，本版不开放。

## 六种配方（开发说明含发现内容）

| 辅助车 | 执行武器 | 联动 |
| --- | --- | --- |
| 风扇 | 火炮 | 风压贯穿炮 |
| 冰霜 | 火炮 | 冻结碎裂炮 |
| 风扇 | 喷火 | 聚焦火流 |
| 冰霜 | 喷火 | 冷热爆破 |
| 风扇 | 电弧 | 聚怪电涡 |
| 冰霜 | 电弧 | 冻结传导 |

六种配方均不分前后。风火统一为由喷火车发射的聚焦火流；本版不再提供火焰龙卷或进攻车之间的燃烧爆弹、破甲磁弹、点燃跳电，也不再提供风扇＋冰霜的暴风雪。

工坊显示辅助者和执行者的实际槽号。战斗触发时，连接上的能量由辅助车流向武器；弹道或电流从武器位置出发，目标范围效果仍在命中处展开。无需在两车中间增加第三台装置。

## 构筑示例

- 火炮—风扇—喷火：中间风扇支援两侧武器，两条联动。
- 风扇—火炮—冰霜：两种辅助集中在同一门炮上，两条联动均保留并独立触发。
- 火炮—喷火—风扇：仅喷火得到风扇支援，一条联动。
- 风扇—火炮—冰霜—喷火—风扇：五槽形成四条联动，两门进攻武器各接受两侧辅助。

当前两种辅助分别触发自己的联动攻击，并非把所有效果强行合成每一颗普通炮弹。规则避免一条联动覆盖另一条；以后新增车厢和词条仍应遵守职责清楚、效果可见的约束。

## 其余规则与迁移

工坊支持五个功能槽的插入、换位、空位交换和满槽替换。新车点击空槽时直接装入；点击已占槽且仍有空槽时，优先找右侧最近空槽，将点击位到空槽之间的车厢右移一格。右侧没有空槽时，找左侧最近空槽，将该段车厢左移一格，再把新车放入点击位。只有五槽全满时才拆除并替换点击的旧车。

插入保留全部旧车的相对顺序、对象ID、等级与攻击冷却。相同两节车厢的配方冷却在插入移位、临时断邻、换位和前后交换后保留，工坊中不推进冷却；只有真正被替换拆除的车厢才清除其冷却记录。新车待安装时可放弃，不能重复领取已经选择的卡牌；安装或放弃前禁止槽位交换，避免点击安装时误换旧车。

工坊有三个主动入口：战斗底栏「调整车序」、点击战场车厢、暂停页「调整车序」。进入后战斗保持冻结，依次点击两个槽位交换，支持与空槽交换；从战场点击进入会先选中对应车厢。暂停的战斗或工坊可以进入调整，未领取补给的暂停页需先返回补给完成选卡，不能绕过奖励流程。

废料累计达到8、24、48、80、120、170时触发六次补给，废料来自真实击杀。前四次均为车厢三选一，可填满四个初始空槽；后两次为两个车厢选项和一个可用词条，无可用词条时回退为三个车厢。首次固定提供风扇、冰霜与一个进攻选项，让初始火炮可以直接获得辅助。

改装只出现当前存在且未满两级的目标：对应车厢类型，或已经形成的联动。车厢改装作用于当前同类型车厢，新安装车不继承被拆车等级；联动等级上限同为两级。已有弹道和持续伤害区保留创建时伤害快照。

首领在60秒出现，击杀即胜；80秒首领仍存活则超时失败，装甲归零则失败。工坊、补给与暂停不推进模拟；1×/2×/4×均按同一个30Hz固定步推进，不跨越补给停点。

图鉴保存键更新到doomsday-recipes-v04。首次迁移保留仍有效的旧配方发现；旧版聚焦火流（fan-flame）迁移到新版flame-fan，旧火焰龙卷记录不冒充已经发现新火流。移除配方仍留在旧存储键中，不删除历史存档。图鉴仅记录知识，不影响数值。

验收关注正反顺序的同一执行武器、共享辅助、集中辅助、不合法配对和能量连接表现。浏览器默认2×，只检查受影响节点。开发固定策略可通关不代表所有组合平衡，更不作为玩家体验结论。

## UI与战场重构

PanelRenderer.ts独立管理菜单、补给、工坊、图鉴、暂停和结算，接受只读展示上下文、绘图接口和点击回调。Game.ts继续负责Cocos节点、资源、战场、输入路由与持久化，面板绘制不推进模拟。

新面板放大车厢图标与点击区域，使用三类职责颜色和明确的“辅助者→执行者”说明。战场连接管线从车厢侧面传递能量，区分风压贯穿弹、冰弹和聚焦火束；受控敌人显示减速环或冰裂纹，首领外围显示蓄力进度。装甲条、倍速与暂停按钮增加独立底板，背景细节收敛以突出战斗。

美术已选定[余晖防线C2](art-directions/SELECTED.md)：手绘暮色环境与少量轻盈战术投影。主菜单、战斗地表分别使用 `afterglow-menu`、`afterglow-ground`；`afterglow-units` 图集拆分车体和武器，实战与卡面共用，实战模块独立旋转；`afterglow-fx` 图集结合动态绘制形成手绘攻击反馈。概念图不改变职责分类、执行武器或六种配方。
