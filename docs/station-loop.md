# 站点选择最小闭环

产品原则：每到一站，做一个能改变下一段战斗的选择。

首次废料补给保留风扇／冰霜／进攻车教学，从第二次补给起，原选卡面板改为站点三选一。仍由既有废料门槛触发，至少间隔12秒战斗时间；第一版没有独立地图或停车动画。

| 站点 | 当场收益 | 下一段代价 |
| --- | --- | --- |
| 废弃货场 | 一节公开类型的车厢，进入现有工坊，可插入、合并或替换 | 至下次补给，每4次常规刷怪追加1名普通怪，受原有敌人数上限约束 |
| 军械站 | 一个当前可用改装，优先进攻车词条，无进攻车时提供其他可用改装 | 恢复战斗3秒后追加1名双血量重甲怪；人数满时延后到有空位，不改变常规首领周期 |
| 维修站 | 最多恢复30点装甲，卡片显示实际值 | 放弃本次车厢／改装；满装甲仍可选择不追加敌人的支线 |

收益与路线绑定。货场即使放弃新车也保留增援代价，避免通过丢弃奖励跳过风险。暂停、工坊、选卡期间冻结战斗、增援与重甲怪延时。下站停止上条路线的新增敌人，已出现敌人保留。重开清空路线与站点计数。

五槽、相邻联动、合并及改装继承规则继续使用。基础难度曲线没有改动，但站点额外敌人会改变实际难度，旧版生存率不代表本站点版平衡。

验收：三站奖励可执行、车厢能装入并继续战斗、风险确实发生、暂停不消耗计时、路线不叠加、重复点击不重复领奖、重开不残留。玩家是否更愿意重开、三个站点是否都有吸引力，需要试玩反馈；规则测试不替代这一判断。

自动检查：`npm run test:stations`。浏览器检查脚本：`tools/check-stations.mjs`，使用已安装Chrome与Playwright，真实点击、2×自然推进到站，结果保存至`artifacts/stations/`。

## 工坊手绘风格修订

用户明确要求精致手绘风格化。工坊沿用`docs/art-directions/SELECTED.md`的余晖防线规范，新增`assets/resources/art/afterglow-workshop-v1.png`：废弃铁路整备所、紫靛与灰粉冷暖叠色、墨线机械边缘，中心留给实际装配。背景由ImageGen参照C2风格图生成，不含烘焙文字或交互元素。

新车以完整车体和武器展示；五槽使用轻量轨道和选位角标，预览显示插入后所有车厢的位置。移位、合并、替换仍使用原有规则。新增/移除联动超过三条时显示前两条及总数，避免侵入出发按钮。普通换位工坊复用同一底画与完整车厢。

## 前一分钟体验打磨

- 首次风扇补给提示放到火炮旁。工坊为已占用槽位留出更多面积，空位收窄；预览以车厢ID追踪位置，点选后新车滑入、旧车移位。辅助到武器的连线在对应槽位间展示方向，未发现配方仍不提前揭晓名字。
- 装车成功保留0.65秒就位过程后出发，期间战斗仍暂停并阻止重复装配输入；低动态模式缩至0.16秒且位置立即就位。换位动画不改变任何战斗冷却或数值。
- 每局首次真实触发风扇—火炮时，显示供能说明并强调对应车厢间的供能路径；贯穿命中特效和“一弹贯穿N名”提示来自同一枚实体炮弹的实际命中名单，不能用总击杀数代替。连破提示在该说明出现时暂时隐藏，避免重叠。
- 站点增加当前编组提示：补进攻火力、可新增联动、同型辅助可合并、满车需替换、当前改装受益以及重甲抗物理。维修继续说明实际恢复量和放弃成长的代价。
- 修复列车驶入期间底栏倍速点击被车厢区域截获的问题：战场车厢命中区域不再覆盖底栏。

专项规则检查：`npm run test:opening`。真实手机尺寸检查：`tools/check-opening.mjs`，证据在`artifacts/opening/`。不新增教学敌人、不清空现有敌人、不修改基础难度，也不保证任何路线都能活过一分钟。

观察到的局部负例：种子137，首次风扇后选军械站自动供弹，再在货场装入第二节风扇（未形成新增联动），45.97秒失守。该路线缺少新增进攻火力，同时承担支线压力；不能据此判定所有军械路线不可用。截图保留为`artifacts/opening/arsenal-duplicate-fan-loss.png`。此负例促使站点提示明确区分新增火力、重复辅助和合并选择。
