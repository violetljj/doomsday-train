# 高效验证流程

适用于后续开发。用户要求提高每轮实际试玩检查效率；测试围绕本轮变化，不重复已经通过且输入未变的检查。

## 按变化选择检查

| 本轮变化 | 必做检查 | 浏览器检查范围 |
| --- | --- | --- |
| 战斗数值、牵引、伤害、波次 | `npm test`，`npm run typecheck` | 只在节奏或可见行为改变时查看对应节点 |
| 图像、材质、布局、动画 | `npm run typecheck`，一次 `npm run build:web` | 相应画面及受影响操作，不重复规则测试 |
| 装配、暂停、强化、重开 | 类型检查与一次构建；有规则修改时补规则测试 | 只走受影响的状态转换 |
| 仅文档 | `git diff --check` | 不启动浏览器或重建 |

## 单次浏览器会话

1. 先完成代码和静态检查，再构建；相同源码不重复构建。复用本轮预览服务、标签页和390×844视口。
2. 开始前确定本轮验收点。战斗已有自然停点：8秒补给、装配、25秒强化、60秒结算。在这些节点读取一次状态，按实际需要截一次图。
3. 每个节点合并读取 `__doomsday.snapshot()` 和该轮日志增量；只在检查外观或定位交互时截图，不为时间推进反复截图、轮询。
4. 检查可以在一局中串联：装配、强化、尸潮、结算。两条路线的规则正确性由快速模拟覆盖；只在分支外观或行为各自变化时分别查看，不因分支存在就完整重跑两局。
5. 常规迭代只查改变的节点；交付前完整跑一局正常速度的整合检查。未改动部分通过后直接复用记录；修复失败项后只复查受影响部分。
6. 等待战斗自然推进时完成差异检查、记录整理等独立工作。收尾时关闭本轮临时标签页和服务，保留构建、日志与验证记录。

浏览器检查、规则模拟和抖音真机分别记录。当前只完成前两类；模拟加速结果不能当作设备帧率或真实游玩节奏证据。不通过调试接口篡改状态来冒充完整操作结果。
