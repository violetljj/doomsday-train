# 爽感与构筑案例参考

日期：2026-09-06。起点是用户对0.2的试玩反馈：尚未感受到爽感或构筑搭配的乐趣。本次仅研究与提出下一轮取舍，未据此修改战斗规则。

## 资料与证据范围

使用Exa查阅官方商店、发行商说明和开发者直接采访。以下把资料事实与设计推论分开。没有在本次研究中亲自试玩这些游戏，也没有验证它们在抖音平台的成绩；已有市场表现不能证明某个单独机制导致成功。

### Vampire Survivors：连续成长与反馈

官方商店强调选择带来的快速成长、成群敌人，以及收集宝石和集中升级少数武器。开发者Luca Galante在2022年The Verge直接采访中谈到：低操作量意味着声音、动画和奖励序列的反馈需要仔细打磨；他希望降低获得强反馈所需的操作门槛。采访同时描述了从单武器、少量敌人到多武器、大量敌人的过程。

设计推论：爽感需要清楚的成长前后对照，还需要把击杀、收获、升级连成一条短循环。对本项目而言，杀敌进度直接带来改装，比单纯等待18/40/58秒更能建立行动与成长的联系。不能据这份采访推断必须使用某种抽奖包装。

- 官方商店：https://store.steampowered.com/app/1794680/Vampire_Survivors/
- 开发者采访：https://www.theverge.com/2022/2/19/22941145/vampire-survivors-early-access-steam-pc-mac-luca-galante

### Brotato：短波次反复检验选择

官方商店列出最多六件武器、多种角色特性和物品、20—90秒波次，以及波次之间用材料购买物品的流程。商店显示该游戏获得大量好评，可作为已被广泛玩家接触的参考；不将瞬时评价数当作设计效果量。

设计推论：一轮战斗暴露问题，购买阶段给出调整机会，下一轮很快检验调整。数值强化不天然无聊；在角色、武器和有限资源约束下，同一个数值对不同搭配的价值可以不同。对本项目而言，先建立可辨识的打法与资源取舍，再扩充卡池数量。

- 官方商店：https://store.steampowered.com/app/1942280/Brotato/

### Backpack Battles：组合关系可见，摆放与合成有意义

发行商松竹2025年5月23日公告标题披露累计销量达到一百万份。其玩法说明明确提及有限背包空间、相邻物品互动、特定物品合成为新装备，以及自动对战。两根长矛合成长矛的实例也体现了合成收益与空间占用之间的关系。

设计推论：自动战斗可以承载构筑乐趣，但玩家需要能主动安排、追求、检验的组合关系。对列车可以先使用少量功能车位和清楚的配方预告；没有必要直接移植复杂背包、PVP或大型合成表。

- 发行商公告：https://game.shochiku.co.jp/blog/news/achieved-1-million-units-sales-worldwide/
- 官方商店：https://store.steampowered.com/app/2427700/Backpack_Battles/

### 向僵尸开炮：同类移动端补充参照

TapTap游戏介绍强调局内随机技能搭配；其页面所列2026年7月更新描述了由冰暴发生器与干冰弹融合、替换技能形态并施加易伤的具体机制。这里只采用玩法说明，不采用介绍中的“爽感拉满”等营销词作为玩家体验证据，也不引用未经原始数据核实的畅销榜名次。

设计推论：组合可以同时改变技能形态和作用规则。可以借鉴“凑齐后明确改变攻击”的表达，不需要先搬入大量局外养成。

- 游戏介绍与更新：https://www.taptap.cn/app/583688/all-info

## 对0.2的判断

当前补给按时间触发，核心风扇固定获得，支援三选一后主要独立工作，六项强化平行抽取。虽然规则有作用，但玩家对后续部件的具体期待较弱。这个判断结合代码结构和用户反馈提出，不是成功案例的直接结论。

## 建议的下一轮范围

先验证一段30—45秒的核心体验，保留现有版本作比较：

1. 击杀积累废料并推动改装，让清场马上推进成长；普通敌人承担清场反馈，少量耐打目标承担压力。
2. 只做两条明确组合：风扇聚怪后，电弧在怪群之间传导；冰霜冻结后，后续攻击击碎并溅射。两者必须有规则和战斗结果的区别。
3. 选择时展示已有部件、下一步配方与组合后效果；提供合理获取机会，让随机性影响路线而不长期剥夺成形机会。
4. 每次关键改装后很快出现一次可检验的尸群；同类敌人在升级前后有可见的清理差异。火焰大小不能替代实际击杀反馈。

验收关注：用户能否描述这局在凑什么、能否指出哪次改装明显改变战斗、是否主动想换路线再试。暂不以新增系统数量、六组合通关率或纯特效密度作为爽感验收。实现细节与数值需另行确定，不把建议写成已验证结果。

后续实际浏览器验证按用户要求默认2×定点检查；只有需要判断正常动画节奏时短暂切回1×。
