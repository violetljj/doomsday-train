# 构筑与联动改造：第一轮范围

用户反馈：构筑系统和联动系统深度不足，优化重心从背景转回玩法。

## 当前证据

- Combat.basicShots 中散射、连发改变火炮普攻，triggerLink 中风压贯穿、冻结、蚀甲等独立发射，不继承这些弹道改装。
- BuildProgression 的主要被动为武器、联动、辅助和废料倍率；配方数量并不等于构筑决策深度。
- deriveCrossfeed 已有两侧辅助共享冻结、腐蚀载荷，但范围仅火炮和轨道炮，不能描述为完整组合系统。
- 60局开发策略诊断中破晓14/20、鸣雷19/20、守望20/20存活至180秒。破晓的6个败局有2局在一分钟内结束，但脚本偏好第一个同分奖励、优先尾部空槽，不能据此认定武器需要直接加伤害。逐次受伤证据见 artifacts/optimization-20260910/engine-loss-diagnosis-v1/report.json。

## 第一段可玩改造

先实现火炮改装与现有联动弹组合：辅助决定弹丸功能，武器改装决定投射方式。散射作用于贯穿、冻结、蚀甲弹；序列连发也保留这些弹的完整载荷。已有双侧供弹继续作用于每颗子弹。保持五槽、相邻关系和进攻车执行，暂不新增车厢或凑数配方。

约束：多弹必须应用明确的单发伤害衰减，不将每颗子弹当成满伤原弹；穿透、冻结、腐蚀和来源记录不能在克隆时丢失。延迟弹在发射时锁定载荷和瞄准方向；换位按原车id跟随，拆车取消未发射弹，暂停冻结队列。防卫/维修的恢复收益每次联动仅一次，不能被弹丸数量倍增。棱镜多弹与散射叠加需要总弹数上限和完整实测，不能只通过复制生成无限弹。

## 验收

1. 相同阵型仅改变散射/连发，联动弹的数量、方向、发射间隔可观察地不同。
2. 每颗子弹保留原配方及元素载荷，命中规则通过实际战斗模拟验证。
3. 暂停、换位、替换以及恢复收益不会产生重复结算。
4. 同种子对照记录总伤害、清群、首领压力与存活，不以单一存活率掩盖过强组合。
5. 工坊词条描述和联动预览说明这种组合，浏览器里能观察到变化。

这份文档是下一段实施范围，不是已实现或已验收的功能。长期仍需处理流派分叉、机会成本、成型后的演化与奖励针对性。

## 第一段实施进展

已实现火炮六类辅助联动弹继承散射和序列连发。单发伤害沿用普攻的 `1/sqrt(散射弹数)` 与连发一级0.72、二级0.6倍率，弹体半径随散射缩小。棱镜与二级散射每轮最多9颗，最多两轮延迟追加；共享延迟队列上限60。恢复、充盾、联动发动计数仍只触发一次。延迟弹保存独立载荷，移动时跟随原车位置，拆车取消；已发射弹不受后续改装变化影响。

规则覆盖六种辅助、双侧冻结腐蚀、独立id/命中列表、实际冻结命中、换位、暂停、替换和恢复次数。18组测试、字体覆盖和类型检查通过。同种子12×3车头×2臂对照共72局，三款180秒存活局数维持8/12、11/12、12/12，平均击杀变化不到2，平均首领击破不变。完整参数、源码哈希与逐局记录见 artifacts/optimization-20260910/linked-cannon-mods-v1/report.json。

未完成：浏览器连接中断，弹幕观感与新文案实际布局待验收；专项成型配装强度、火炮之外的武器演化、流派取舍与奖励针对性仍需继续。不能将这一段视为完整构筑系统重做完成。
