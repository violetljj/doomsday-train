# 末日列车

项目根目录：`E:\Doomsday Train`。

目标是制作未来上线抖音的小游戏。当前为 Cocos Creator 3.8.8 可运行原型0.2.0：自动战斗、风扇装配、三种支援车、两种龙卷进化、随机强化与关底首领。单局最多90秒战斗时间。已进行本地 Web 构建及浏览器操作检查；尚未验证抖音真机、广泛玩家体验或商业化。

## 立即试玩

双击根目录的 **玩一下.cmd**。它启动本地服务并打开默认浏览器；试玩时保留启动窗口，结束后在窗口中按 Ctrl+C 停止服务。首次没有 Web 构建时会自动调用本机 Creator 构建。

操作：点击发车；8秒领取并装配风扇；18秒选择支援车；25秒选择双生或巨型龙卷；40、58秒各选一次强化。70秒首领出现，90秒前击败首领获胜，装甲归零或超时失败。底部可暂停、切换声音或减弱镜头震动。选卡与装配不消耗战斗时间。

底栏新增 **倍速 ×1** 按钮，点击按 **1× → 2× → 4× → 1×** 循环。用于调试，战斗计时、敌人、攻击和特效一起加速；选卡、装配与暂停照常停止。重开保留本次倍速，刷新页面回到1×。倍速结果不作为正常速度的手感或设备性能证据。

修改代码后运行 `npm run build:web` 更新试玩版本，再运行 `npm run serve`。`npm test` 检查战斗规则，`npm run typecheck` 检查 TypeScript（需先完成一次构建）。本机已验证 Node.js 24.16.0；规则测试使用其 TypeScript 类型擦除能力。

后续按[高效验证流程](docs/validation-workflow.md)选择检查范围：模拟覆盖规则，浏览器默认2×抵达新增节点；通过且未改动的部分不重复测试，不固定要求每次完整试玩。

在 Cocos Dashboard 中导入本目录，使用 Creator 3.8.8 打开 `assets/scenes/Main.scene`。实际验证的是 Creator 命令行构建和浏览器运行，尚未逐项检查编辑器 UI 工作流。

核心代码：`assets/scripts/Combat.ts` 为固定步战斗规则，`assets/scripts/Game.ts` 为画面、输入和声音。构建输出在 `build/web-mobile/`，构建日志在 `logs/`。本地结果保存在浏览器 `doomsday-last-run`，不上传服务器。

## 已确认的产品方向

列车改装＋自动割草，优先做爽感。玩家亲手组装越来越强的列车，用不断变化的火力突破尸潮。

- 低操作：列车自动行驶、自动攻击，玩家主要负责选择和装配。
- 强成长：关键改装明显改变攻击形态、覆盖范围或攻击节奏。
- 战斗节奏：尸潮施压 → 关键升级 → 成片清场 → 更强尸潮。
- 搭配服务于爽感：组合易懂，减少无效配对和繁琐换位。
- 反馈清楚：玩家看得见命中、敌人倒下和道路被清开，并能理解变化来自哪次改装。

## 本轮机制扩展 0.2.0

- 18秒三选一支援车：电弧车连锁清群、冰霜车减速控场、维修车持续修复装甲。接到风扇车后形成更长列车，并在战斗中自动生效。
- 40、58秒各一次随机三选一强化：热能、供弹、范围、击杀爆破、支援超频或装甲。每项最多两级，卡牌即时生效；同一种子与选择可复现。
- 70秒出现关底首领“破阵者”，有独立血条和冲击蓄力。主炮优先攻击首领；击败它才算突围，不再到60秒自动获胜。90秒仍未击败则超时。
- 结算展示本局主炮、支援车和强化，便于重开对比搭配。沿用现有美术，新增内容先以可读的机械图形和效果呈现。

## 上轮改进 0.1.2

- 炮台锁定目标，按最短方向平滑转动并在接近目标时减速，避免最近目标变化导致左右瞬跳。喷火和龙卷沿炮口发出。
- 风扇补给图标改为完整装甲风扇车，带轮组、车钩、金属护圈与五片扇叶；与实际装车后的机械结构共用绘制代码。
- 加入1×、2×、4×调试倍速，保留固定步战斗和暂停停点。

## 上轮打磨 0.1.1

- 龙卷使用火焰旋臂贴图叠加发光，保持中心和旋臂间隙通透；补上拖尾火星、命中闪光、击杀甩出与连续击破提示。
- 敌人受最近一道龙卷牵引并绕流，牵引位移有上限；每道龙卷保留生成时的伤害，升级不改写已经飞出的攻击。
- 5、21、45、50秒出现集中尸群；8—11、25—29秒降低新敌人生成，形成升级后清场的喘息段。50—57秒为最后高压段，最后3秒收束；没有升级回血或虚假击杀。
- 新增机车同风格的装甲车厢贴图，重绘炮塔与风扇。双生强化显示两座炮塔，巨型强化增加大风扇与散热部件。
- 放大手机上的生命、击杀、阶段和底部控制文字，把提示移到列车上方，减少遮挡。

## 当前单局节奏

当前机制由首个一分钟原型扩展而来，数值和节奏仍待试玩反馈调整。

核心片段：基础喷火 → 接上风扇车 → 火焰龙卷扫穿怪群。

| 有效战斗时间 | 体验 |
| --- | --- |
| 0—8秒 | 基础喷火抵挡少量僵尸，建立改装前的参照。 |
| 约8秒 | 战斗暂停，固定获得风扇，玩家完成第一次装配。 |
| 8—18秒 | 龙卷穿过怪群，清楚展示攻击变化。 |
| 约18秒 | 电弧、冰霜、维修三选一，接入一节支援车。 |
| 约25秒 | 选择双龙卷或更粗、更持久的巨型龙卷。 |
| 40、58秒 | 两次随机三选一强化，形成不同侧重的搭配。 |
| 70—90秒 | 在尸潮压力下击败首领；胜负结算并展示本局搭配。 |

选择和装配期间冻结战斗；实际一局时间包含操作时间，可能超过90秒。初始装甲100，装甲强化可以提高上限，敌人活动上限100。同一步先判列车死亡。原型采用点击装配，尚未做自由拖动车厢。

已完成的开发增量：

1. 列车、敌人、基础喷火、受伤、结束与重开，形成基础战斗。
2. 风扇装配和真实龙卷攻击，完成首次质变。
3. 两种强化、最后一波与清场反馈，打通短局。

首轮重点观察：玩家是否理解改装导致的变化，改装后的攻击是否更有爽感，是否愿意主动重开尝试另一条强化。程序正确和真人觉得好玩分别记录。

## 美术资产制作

用户已授权使用 imagegen 生成游戏所需的图像资产。当前机车、僵尸、车厢装甲表面和火焰旋臂已由内置 imagegen 生成并接入 `assets/resources/art/`；完整提示词、尺寸与检查在 `docs/art-prompts.md`。炮管、风扇、轮组、场景和命中反馈由引擎绘制或驱动。

机车与僵尸使用真实透明图。装甲表面是有意不透明的金属纹理，火焰是黑底发光贴图，通过加法混合渲染。曾生成的车厢/炮塔切图及背景提取均未通过透明检查，未进入游戏资源；不把烘焙棋盘格当作透明。

- 默认使用内置 image_gen，遵循 imagegen 技能；此授权不要求另行使用付费 CLI/API 路径。
- 同批资产保持一致的视角、比例、光照和轮廓风格；透明精灵要求真实透明背景，并检查边缘及小尺寸可读性。
- 为装配、炮管转动、风扇旋转等用途分别制作所需部件；火焰、龙卷、爆炸的运动和命中反馈由引擎实现，可使用生成的贴图。
- 项目使用的最终图片保存到本项目目录，保留提示词和生成方式，方便后续保持风格或修改。
- imagegen 用于图像制作；声音、音乐及游戏逻辑分别制作和验证。
